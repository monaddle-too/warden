Warden, on your Mac.

A private development VM, an enforcing proxy, and approvals you control.

Local preview for Apple Silicon. Drag Warden.app into Applications, then open it. This local build is ad-hoc signed, not Apple-notarized. The DMG metadata records the minimum macOS version required by its bundled tools.

  1. Choose Set up Warden. Warden uses your existing local installers if available. Otherwise, choose their folder once. It verifies the files, prepares the disks and installs macOS automatically.
  2. Let setup run. The window shows what is happening. You can open Details for logs. If setup is interrupted, it keeps completed steps so you can continue.
  3. Open Warden. When setup finishes, open your development Mac. Complete macOS's welcome screens and sign in to your tools. First proxy boot needs internet access for Linux packages; this preview does not include an offline package repository.
  4. Connect your guest. Choose Finish guest setup when it appears. In the VM's Terminal, run sudo warden-trust-proxy and enter the printed username and SHA256 fingerprint in the connection dialog. If guest access is not yet installed, run curl -fsS http://10.77.0.1:8081/install-guest-access.sh -o /tmp/warden-access.sh && bash /tmp/warden-access.sh.

Optional customization

Customize… lets you choose the installer folder and an empty storage folder before setup. You can also turn off automatic macOS installation to prepare images now and install later. Recommended defaults keep VM state in Application Support. Existing environments keep their current location.

Your state stays separate

Disks, policy and credentials live in ~/Library/Application Support/Warden. Replacing the app does not replace that directory. Shut down the VM and stop its host services before replacing or moving an app that is in use. This preview has no automatic DMG updater.

The bundled CLI is /Applications/Warden.app/Contents/MacOS/warden. Use services stop after the VM shuts down. Setup logs are available under Details; runtime logs live in the state folder.

Local build scope

Host Python, Node and QEMU are bundled; Homebrew and Command Line Tools are not needed to launch or prepare. VM installers are separate local inputs, not included in the DMG. No personal state is included. Guest tools still need their ordinary sign-in and any first-run setup.

Apple notarization, a fully offline first proxy boot, public distribution review of third-party components, and automatic app updates remain outside this local preview.
