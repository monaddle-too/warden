Run these commands inside the guest. GitHub credentials stay on this host. Approve a repository read session when checkout first pauses; each publish requires its own review here.

warden-repo clone OWNER/REPO
cd REPO
warden-repo branch my-change
warden-repo setup
# Make changes, then commit them in the guest.
warden-repo check
warden-repo review
warden-repo publish
warden-repo pr --base main --title "Describe the change"

Read session: one repository, up to one hour; revoke it in Active permissions. Publish: one branch, exact content, once. Warden independently verifies the outgoing commits and shows their patches before authorization.

Publish waits for approval and retries only after an explicit HTTP 428. Transport errors require checking remote state; writes are never blindly replayed.

Workflow limits

Use HTTPS remotes ending in .git. Pushes must be text changes on one branch, at most 8 MiB of packed objects and 256 KiB of review text. Force pushes, deletions, tags, submodule updates, binary changes, and incomplete reviews are blocked. GitHub branch protection still applies.

Setup installs locked dependencies without lifecycle scripts by default. Run project scripts explicitly inside the guest. Public npm and Python registry downloads use normal inspected HTTPS; dependencies hosted on another GitHub repository need their own read approval. GHCR and GitHub release downloads remain blocked.

Hosted AI search and connectors can access remote content through allowed AI services. This workflow does not close that separate egress gap.

Separate projects and recovery

./warden project create PROJECT --repo OWNER/REPO
./warden project run PROJECT -- setup --apply
# Shut down the guest before taking a disk checkpoint.
./warden recovery capture before-change
./warden recovery verify before-change
# Stop the controller before restoring.
./warden recovery restore before-change

Each project gets separate disks, credentials and policy. Checkpoints contain VM disks; treat them as confidential. Restore keeps current host policy and audit and starts with the network disconnected.

Security scope of this build

Outbound HTTP(S) and DNS follow the selected destination policy. Allowed AI providers can receive source code and may provide remote tools. GitHub REST and repository reads require approval; each Git push requires an exact reviewed permission. GitHub web, GraphQL, unsupported Git transfers, SSH, QUIC, private-network destinations, and opaque protocols are blocked. Exact approvals are single use; scoped permissions match one operation and exact URL, with optional body constraints.

Prototype undergoing validation. It has not received an independent security audit.

Example: {"/base":"main","/draft":true}. Other fields may vary. An empty object permits any JSON body.
